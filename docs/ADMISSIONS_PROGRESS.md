## Non-duplication rules

- Store shared university rules once; programmes contain only their distinct conditions. An additional international requirement must not repeat rules already applicable to all applicants.
- Identity is exact institution + existing programme (or university-wide) + academic year + intake + level + route + applicant group + stable meaning-based fact key. Source URL is evidence, not a new fact identity.
- Merge synonymous findings manually under the same key. Automated checks reject duplicate keys/text within a dataset and skip existing matching facts even if the URL or label changes. They cannot reliably detect every paraphrase; source review is still mandatory.
- Same key with different content/status is a conflict requiring review, not permission to overwrite. Different years, qualification systems and applicant groups must retain their conditions; do not merge incompatible thresholds.
- The initial general-facts importer is append-only: it does not change existing facts/profiles, remove old rows, create schools/programmes, or take ownership from another provider. Additional corroborating sources for an existing fact are reported as skipped, not appended as duplicate requirement rows. Curated multi-source evidence merging is a future enhancement.
- IB facts remain in the dedicated structured IB section. Do not paste their full conditions into general requirements again.
