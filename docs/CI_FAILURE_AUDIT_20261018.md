## Additional defects corrected during this audit

- Migration paths used `URL.pathname`, which retains `%20` for spaces. A checkout under `project with spaces` therefore pointed to a nonexistent `project%20with%20spaces` directory. `fileURLToPath` now produces the real filesystem path.
- A failed migration skipped `connection.close()`. Cleanup now runs in `finally`, and a failed migration still exits with the original error. Two lifecycle regression tests cover success and failure.
- The official-programme data-quality guard used `<>` on a nullable academic year. SQL yields unknown for a null year, so that missing value could evade the guard. `IS DISTINCT FROM` now detects it.
- README still said the admissions importer could never create programmes, contradicting its reviewed programme-declaration feature. The instructions now describe the actual supported workflow.

## Regression prevention and verification

The existing `quality` job retains formatting, lint, typecheck, tests and build as individually named steps. A manual workflow trigger allows checking the current branch. Formatting standards remain enabled.

A separate PostgreSQL 18 CI job checks out the project into a directory containing spaces, applies all migrations to an empty temporary database, and runs them again to verify idempotence. It requires no repository database secret and does not access the website's database.

Local `pnpm check` passed all stages with **146 tests in 23 files**. The specific historical hand-edited files were checked again and passed. The data-quality shell script passed syntax validation. Docker was not running during this audit, so no local live-database check or website rebuild is claimed; the new GitHub database job provides the integration verification. The published revision and remote CI outcome are recorded in the task handoff.
